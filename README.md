# Профиль Кости Дербышева

Статический сайт для GitHub Pages (ветка `main`, корень репозитория). Сборки нет: `index.html`, `career.html`, `mama.html`, `styles.css` и `app.js` рисуют страницы из `data.json` и `news.json`.

Стиль — тёмно-золотая карточка игрока с аркадными акцентами в духе NBA Jam: косые заголовки, огненные полосы, большой номер на фоне карточки и бегущая строка итогов. Блоки выезжают при прокрутке, цифры досчитываются до значения из данных, столбцы растут, страницы сменяются переходом (View Transitions). При `prefers-reduced-motion` всё это выключено, цифры стоят сразу.

На графике очков победы золотые, поражения серые, пунктир — среднее по этому журналу. «В огне» — три матча подряд и больше, где очков не меньше двух средних. Порог считается из строк журнала, вручную не задаётся. Бегущая строка собирается из тех же данных, что и карточки карьеры.

Заголовки и цифры — Oswald, текст — Onest. Оба шрифта с кириллицей, цифры с `tabular-nums`. График очков рисуется по ширине карточки: от 360 px помещаются все матчи, даты через одну, если подписи не влезают. Столбцы сравнения сезонов не шире 560 px и высотой 260 px.

На сайте имя — «Костя Дербышев». Отчество, точную дату рождения и ссылку на личную карточку игрока не добавляйте. Год рождения и названия команд можно.

## Карьера

`career.html` считает карточки из уже лежащих данных. Новые цифры туда вручную не вписываются:

- игры и сумма очков — по строкам `gameLogs`;
- лучшая игра — максимальные очки в этих строках;
- место — число из текста результата в `lastMatch`, если там есть «3-е»;
- максимумы очков и перехватов — из `tournamentStats.seasons`;
- подборы и передачи 2025/26 и сравнение с прошлым сезоном — из `trend`.

Полосы сравнения — доля от лучшего среднего среди трёх турниров. Это не оценка от 0 до 99.

## Для мамы

`mama.html` берёт строки последних игр из журнала U12 по датам в `mama.games` и дописывает короткий плюс из поля `plus`. Числа в `plus` должны совпадать с журналом и с блоком «Последний матч».

Игра без личного протокола лежит в `mama.pending`. Туда можно писать счёт команды из новости клуба и прямо сказать, что очков Кости нет.

## Новости команды

`news.json` пополняет `scripts/update_stats.py`. Уже лежащие записи скрипт не переписывает: та же ссылка остаётся с вашим заголовком и текстом. Новые посты он берёт из публичной ленты Telegram `t.me/s/rostokmsk` и со страницы `rostokmsk.ru/news`. Метка `2014`, если в тексте есть «2014», иначе `клуб`. Совсем короткие посты без букв (одни эмодзи) пропускает.

| Поле | Что писать |
| --- | --- |
| `caption` | Одна строка над списком |
| `sources` | Ссылки на Telegram, VK и сайт клуба |
| `posts[].date` | `ГГГГ-ММ-ДД` |
| `posts[].sort` | Если дата одна, большее число стоит выше |
| `posts[].tag` | `2014` или `клуб` |
| `posts[].title`, `text` | Короткий пересказ. Счёт команды можно, личную статистику Кости из новости не выводить |
| `posts[].link` | Ссылка на пост, только `http` или `https` |

Фильтр на странице: «Все», «2014», «Клуб». Блок есть на карьере и на странице для мамы. Скрипт кладёт посты других команд и объявления клуба в метку `клуб`.

## Что ещё можно добавить

1. Когда появится личный протокол сезона 2026/27, добавьте строку в журнал. Карточки карьеры пересчитаются сами. Имеет смысл завести отдельный турнир в `gameLogs`.
2. Фото в щиток — только свой кадр.
3. Карта бросков — только если в протоколе будут координаты.
4. Сравнение с командой — когда опубликуют средние состава.
5. Общий рейтинг, цветные плашки и уровни бейджей не добавлять: таких чисел в протоколах нет.

Локальный просмотр (нужен HTTP, не открытие файла):

```bash
python3 -m http.server 8000
```

Дальше откройте `http://127.0.0.1:8000/`.

## Структура `data.json`

Корень — объект с блоками страницы. Порядок разделов задаёт массив `nav`. `label` — заголовок на странице, `short` — короткая подпись в полосе меню: Матч, Профиль, Сезон, Турниры, Игры, Динамика, Оценка, Источники. На телефоне эта полоса липкая и появляется после карточки игрока. Шапка с именем прячется при скролле вниз и возвращается при скролле вверх.

| Ключ | Что на странице |
| --- | --- |
| `player` | Шапка: `name`, `number` (цифра в шестиграннике), `team`, `position`, `summary` |
| `nav` | Меню разделов: `id`, `label`, `short` |
| `lastMatch` | Блок «Последний матч» |
| `profile` | Карточки профиля и абзац |
| `season` | Матчи сезона 2026/27 без протокола и таблица группы А |
| `tournamentStats` | Средние и броски по турнирам |
| `gameLogs` | Переключатель поматчевых журналов |
| `trend` | Столбчатое сравнение сезонов |
| `notes` | «Что уже получается», «Над чем работать», короткий вывод |
| `mama` | Тексты страницы «Для мамы»: вступление, плюсы к играм, игра без протокола |
| `sources` | Ссылки на турниры |

Десятичные в JSON пишутся с точкой (`4.3`). На сайте средние показываются с одним знаком и запятой (`4,3`): так же, как `toFixed(1)`. Целые в журналах остаются целыми (`11`, не `11,0`). Строки бросков (`"14/57, 25%"`) копируются как есть, сайт их не пересчитывает.

Поле `"highlight": true` выделяет строку команды или сезона. В таблице группы оно стоит у «Росток-2014», в средних — у сезона 2025/26.

### Средние, `tournamentStats.seasons`

Оба блока (средние и броски) читают один и тот же массив. Колонки: `averageColumns` и `shootingColumns`. У средней колонки `"average": true`.

Поля сезона: `name`, `games`, `minutes`, `points`, `rebounds`, `assists`, `steals`, `turnovers`, `fg2`, `fg3`, `ft`.

### Журналы, `gameLogs.tournaments`

У турнира есть `id`, `label`, `columns` (`key` + `label`) и `rows`. Открытый по умолчанию турнир — `gameLogs.defaultId` (`u12`).

График очков рисуется только если у турнира есть `chart`:

- `labelKey` — поле подписи (у U12 это `date`);
- `labelPrefix` — сколько первых символов взять (`5` превращает `28.09.25` в `28.09`);
- `valueKey` — поле высоты столбца (`points`).

У «Быстрого прорыва» и «Движения вверх» графика в исходных данных нет, только таблицы.

### Динамика, `trend.views`

Два переключателя: `avg` («Игра») и `ctrl` («Контроль мяча»). У вида есть `categories` и `series`: имя серии и массив `values` той же длины, что и категории. Значения — средние за игру, на графике подписываются с запятой. Какой вид открыт сначала, решает `trend.defaultId`.

Фолы и «фолы на нём» есть только в виде `ctrl`, в таблицах средних их нет. Меняйте эти числа прямо в `values`, сайт их не выводит из журнала.

## Добавить игру в журнал

1. Откройте нужный турнир в `gameLogs.tournaments`.
2. Добавьте объект в конец `rows`. Ключи те же, что у соседних строк.

Пример для «Росток U12»:

```json
{
  "date": "ДД.ММ.ГГ",
  "opponent": "Соперник",
  "score": "00:00, победа",
  "minutes": "00:00",
  "points": 0,
  "fg2": "0/0",
  "rebounds": 0,
  "assists": 0,
  "steals": 0,
  "turnovers": 0
}
```

Если у турнира задан `chart`, новый столбец появится сам. Сайт сам средние не суммирует. Для сезона 2026/27 это делает `scripts/update_stats.py`: журнал `mos2627`, строка средних и блок «Последний матч» собираются из протокола. Заметки «Что получается», сравнение `trend` и старые журналы скрипт не меняет.

Новый турнир — ещё один объект в `tournaments` со своим `id`, `label`, `columns` и `rows`. Чтобы открывать его кнопкой, этого достаточно. График очков включите объектом `chart`, если в строках есть числовое поле очков.

## Обновить таблицу группы

Правьте `season.standings.rows`. Колонки: `team` (с местом, как `6. Росток-2014`), `played`, `wins`, `losses`, `points`, `scored`, `conceded`. Все значения — строки, чтобы не появилась лишняя десятая.

У строки «Росток-2014» оставьте `"highlight": true`, у остальных это поле не нужно. Подпись даты в `season.caption` тоже обновите, например: «По состоянию на 2 ноября 2026». Пока в таблице нули, а счёт уже есть в `season.matches`, на странице висит `season.plaque` — короткая плашка вроде «Таблица ещё не обновлена: победа 62:37». Скрипт обновления сам снимает плашку, когда у «Ростка» в таблице появятся сыгранные игры.

## Заменить блок «Последний матч»

Полностью замените объект `lastMatch`.

- `caption` — что считается последним протоколом и какая игра ещё без протокола.
- `facts` — три карточки: матч, дата и стадия, результат. Можно добавить или убрать карточку: рисуются все элементы массива.
- `columns` и `rows` — протокол. `rows` — массив строк, обычно одна. Число ячеек в строке равно числу колонок.
- `paragraphs` — текст разбора, каждый элемент с нового абзаца.

Текущие колонки: «Старт», «Мин», «Очки», «2-очк.», «Штраф», «Подб (нап)», «Пер», «Перехв», «Потери», «Фолы».

Игру без протокола в текущем сезоне держите в `season.matches` (поля `title`, `detail`, `status`). Когда протокол появится, перенесите цифры в `lastMatch`, а в `matches` смените `status` или добавьте следующую игру в начало массива.

`updated` — день, когда скрипт в последний раз реально поменял цифры или новости. На сайте это строка «Обновлено: …». Дата считается по Москве: так датирует календарь турнира.

## Телефон

На ширине до 720 px шапка и полоса разделов по 44 px и делят одну липкую строку: вместе не выше 44 px. Ссылки, кнопки переключателей и «Наверх» не ниже 44 px. Таблица последнего матча на телефоне — карточки цифр, журнал игр — раскрывающиеся карточки, средние по турнирам — те же сезонные карточки, что на карьере. Таблица группы остаётся таблицей: первая колонка прилипает слева, над ней плашка `season.plaque`, если победа из новости в таблицу ещё не попала.

В карточке игрока четыре средних текущего сезона (очки, подборы, передачи, перехваты) сеткой 2×2. Пока личного протокола 2026/27 нет, это сезон 2025/26 из `tournamentStats`. Рост — мелкой строкой под ними, из профиля.

## Приложение на Android

Сайт ставится на главный экран. `manifest.json`: имя «Костя Дербышев», короткое «Костя», `display: standalone`, цвета фона и темы `#07080c`, `start_url` и `scope` — `/kostya-baske/`. Иконки `icon-192.png`, `icon-512.png` и maskable-пара, плюс `favicon.svg`, `logo.png` / `logo.svg` и `apple-touch-icon.png`: логотип DERBYSHEV 7 (на иконках приложения — только круг с игроком, без нижней надписи). В `manifest.json` у иконок в URL стоит версия (`?v=…`), чтобы Chrome на Android не подставлял старый оранжевый мяч из кэша. Если ярлык уже стоял на экране, удалите его и установите заново (или дождитесь обновления WebAPK, обычно до суток). На iPhone иконка меняется только после переустановки с домашнего экрана.

`sw.js` кэширует страницы и в той же строке подключает OneSignal (`importScripts` их `OneSignalSDK.sw.js`). Регистрирует этот файл только OneSignal, с адресом `sw.js?appId=…`. Отдельный `register("sw.js")` без этих параметров снова ставит второй сценарий на тот же scope и зацикливает перезагрузку. Плашка «Доступно обновление» появляется, когда новая версия уже ждёт, и кнопка «Обновить» включает её один раз. `data.json` и `news.json` запрашиваются сначала из сети и только без сети берутся из кэша, поэтому новая статистика видна без переустановки. Остальные файлы — stale-while-revalidate. Когда выкладывается новый `sw.js`, на экране появляется «Доступно обновление» и через несколько секунд страница перезагружается сама. Кнопка «Обновить» делает это сразу. При `prefers-reduced-motion` анимации по-прежнему выключены, обновление страницы это не отменяет.

Кнопка «Включить уведомления» стоит внизу каждой страницы. При первом заходе браузер сам разрешение не спрашивает. «Выключить уведомления» отписывает от пушей. Галочка «Игры» включается вместе с кнопкой, «Новости команды» — по желанию. В OneSignal это метки `Игры` и `Новости команды` со значением `1`.

## Автообновление

`scripts/update_stats.py` читает публичный JSON `reg.infobasket.su` (тот же, что у fbm-tv.ru) и открытые ленты новостей.

- Календарь и таблица группы А, соревнование `153217`, родительский турнир `142760`. Если команды нет в этом календаре, скрипт смотрит соседние группы в `Widget/CompIssue/142760` и запоминает новый `sync.compId`.
- Личный журнал — `Widget/PlayerStats` и, если строки там нет, протокол `Widget/GetOnline`. Идентификатор игрока живёт только в скрипте. В `data.json`, в новости и в ссылки на сайте он не пишется. Отчество и точная дата рождения тоже.
- Новая игра дописывается в журнал `mos2627`. Средние сезона, «Последний матч» и строка на странице «Для мамы» собираются шаблоном из цифр протокола. Если задан секрет `PERPLEXITY_API_KEY`, для новой игры без разбора скрипт один раз просит короткий текст у Perplexity (модель `sonar`) и пишет его в `aiReview` и `aiMama`. Уже заполненные поля не перезаписываются, даже если в Run workflow включить повторный разбор. Пока полей нет или ключ не задан, на сайте остаётся шаблон. Глоссарий, `mama.seasonSummary`, `achievements` и разборы старых игр скрипт не стирает. В запрос не попадают отчество, дата рождения и идентификатор игрока.
- Пока в протоколе нет личной строки, блок «Последний матч» и старые журналы не трогаются. Счёт `0:0` при статусе «ещё не сыгран» не затирает счёт, уже записанный из новости клуба.
- Если источник не ответил или ответ странной формы, этот кусок остаётся старым, сайт не ломается.

Проверка без записи: `python3 scripts/update_stats.py --dry-run`. Только внутренние проверки: `--self-test`.

Workflow `.github/workflows/update-stats.yml` запускается сам: в субботу и воскресенье каждый час по UTC, в остальные дни каждые 3 часа по UTC, и вручную кнопкой Run workflow. Коммит в `main` делается только когда изменились `data.json` или `news.json`. После слияния этого PR workflow начнёт работать на `main`. GitHub Pages с ветки `main` сам подхватит коммит.

Если в журнале `mos2627` появилась новая игра с личным протоколом, скрипт шлёт пуш тем, у кого метка `Игры` равна `1`. Текст вроде «Новый протокол: Росток 62:37 Гольяново. Костя: 8 очков, 3 подбора», по нажатию открывается раздел «Последний матч». Новая новость с меткой `2014` уходит только тем, у кого метка `Новости команды` равна `1`, и открывает блок новостей. Уже отправленные id лежат в `data.json` → `pushSent`, повторно скрипт их не шлёт. Старые игры и новости при первом запуске только помечаются, без рассылки. Если секрета `ONESIGNAL_REST_API_KEY` нет, отправка пропускается, workflow при этом не падает, и в следующий раз попробует снова.

Что нажать в GitHub, один раз:

1. Settings → Pages → Build and deployment → Deploy from a branch → ветка `main`, папка `/ (root)`. Адрес будет `https://workjobdub-del.github.io/kostya-baske/`. Пока источник не выбран, сайт не открывается.
2. Settings → Actions → General → Workflow permissions → Read and write permissions. В самом workflow уже стоит `permissions: contents: write`, но если в репозитории выбран режим «только чтение», push из Actions не пройдёт. Галка «Allow GitHub Actions to create and approve pull requests» не нужна.
3. Settings → Secrets and variables → Actions → New repository secret. Имя ровно `ONESIGNAL_REST_API_KEY`, значение — REST API Key из OneSignal (Settings → Keys & IDs). Ключ в репозиторий и в сайт не кладётся.
4. Туда же второй секрет: имя ровно `PERPLEXITY_API_KEY`, значение — ключ Perplexity API. Без него разбор не запрашивается, на сайте остаётся шаблон, workflow не падает.
5. Проверка пуша: Actions → «Обновление статистики и новостей» → Run workflow → включить «Отправить тестовое уведомление всем подписчикам».
6. Проверка разбора: тот же Run workflow → включить «Заново сделать ИИ-разбор последней игры с протоколом». Нужны секрет и личный протокол в журнале `mos2627`, у которого ещё нет `aiReview` и `aiMama`. Если оба поля уже записаны, скрипт их не меняет. Новый текст появляется в блоке «Последний матч» и в «Что порадовало» на странице «Для мамы».

Что нажать в OneSignal:

1. Settings → Platforms → Web → добавить сайт как Custom Code, не Typical Site. Site URL: `https://workjobdub-del.github.io/kostya-baske`. Автозапрос разрешения в панели выключить: на сайте он и так выключен.
2. Путь к service worker в коде уже задан: файл `kostya-baske/sw.js`, scope `/kostya-baske/`. Поля «Customize service worker paths» в панели для Custom Code не используются, их можно не заполнять.
3. Settings → Keys & IDs: App ID на сайте уже стоит `7a9c32d2-ee00-46aa-9cfd-009842e4dab4`. Оттуда же скопировать REST API Key в секрет GitHub из пункта выше.
